## 3. Cómo funciona hoy Dropshipping

**Panel** (`montaguth.institute/dropshipping/`, solo admin para leer Dropi):

- Buscar por palabra (24 por página, Anterior/Siguiente) o abrir por id (solo esa ficha).
- Las fotos se pintan **directo desde el CDN de Dropi**: no se guardan.
- «Agregar a la bandeja» → el **carrito** flotante de la esquina suma. Al abrirlo:
  «En curaduría» / «Descartados», con foto, costo, sugerido y stock.
- **Llevar a Campañas**: relee la ficha por id → variante (una variante = una
  campaña) → fotos (todas marcadas, se desmarcan) → nombre de trabajo → crea el
  borrador → abre `marketing/campanas/editar.html?id=…&desde=dropshipping`.
- En la bandeja, lo llevado muestra «Abrir en Campañas» y, si hay más
  variantes, «Llevar otra variante». Un candidato llevado ya no se descarta.

**Base de datos (D2a):**

- `ds_llevar_a_campanas(...)` crea en **una transacción** el producto
  `origen='proveedor'` (SKU `MAG-DROP-NNNN`, **sin** `costo_unitario`), su
  `producto_proveedor` (con `candidato_id`, `variacion_nombre`, costo y stock
  de la relectura; la lectura **nace vencida**: `stock_vence_en = stock_leido_en`)
  y un **borrador** (`publicado=false`, sin sello, sin precio, sin slug).
  Idempotente por producto + variante Dropi. Exige módulos Dropshipping **y**
  Marketing. Solo acepta keys de imagen propias que existen en
  `storage.objects` del bucket `campanas`.
- Gatillo `ds_campana_vinculo_proveedor` sobre `campana_producto`: una campaña
  proveedor no se re-liga ni se des-liga; un producto proveedor solo se liga
  con la compuerta local `impulse.ds_importando` que abre la importación.
- Publicar sigue bloqueado (`DS_PUBLICACION_PENDIENTE`) y `catalogo_publico`
  excluye proveedor.

**Editor de Campañas** con producto de proveedor: aviso «Producto de
proveedor» (Dropi #, variante, costo, SKU), selector de producto bloqueado,
tope de escaparate oculto. Los selectores de producto de `agregar.html` y
`editar.html` listan solo productos **propios**.

## 4. Lo medido que no hay que redescubrir

| Tema | Hecho |
|---|---|
| Acceso a Dropi | Rechaza peticiones sin `User-Agent` reconocido (401). Va en el secreto `DROPI_USER_AGENT` |
| Fotos | Llegan como `gallery[].urlS3` (listado) y `photos[].urlS3` (ficha), **relativas** a `https://d39ru7awumhhs2.cloudfront.net/`; registros viejos traen `url` relativa a `https://api.dropi.co/` |
| CORS de las fotos | El CDN responde `Access-Control-Allow-Origin: *`: el navegador puede traerlas y convertirlas (así funciona D2a, sin Edge Function nueva) |
| Total de resultados | `count` de `products/index` llega **0** con resultados: no sirve. Se pide `tamano + 1` para saber si hay página siguiente |
| Variantes | Nombre en `attribute_values[{attribute_name, value}]`; stock en `stock` o suma de `warehouse_product_variation[].stock`. Un producto `VARIABLE` suma sus variantes (`warehouse_product` viene vacío) |
| Ficha por id | `GET products/v2/{id}` = 200 con ficha y bodegas. `GET products/{id}` = 400 «No tiene permisos» (no usar) |
| SKU de Dropi | Llega genérico (`PRODUCTO`): la llave es el **id** |
| `storage.objects` | El rol del SQL Editor (`postgres`) salta RLS, así que una función `security definer` puede comprobar que una foto existe |
| Bucket `campanas` | Sus policies SELECT/INSERT están documentadas (INSTRUCCIONES C2), no versionadas; INSERT exige `tiene_acceso_marketing()` |
| Fuente del plugin | `github.com/vjcvictor/wc-dropi-integration` (Dropify v4.7.3): `clasess/tables/Product_List.php` y `clasess/models/ProductsModel.php` |

## 6. Cómo se trabaja (para el chat nuevo)

- **Rama nueva + PR por cambio**; nunca push directo a `main`. Migraciones
  **forward**; nunca se reejecuta una histórica.
- **Medir antes de afirmar.** SQL en el repo ≠ SQL desplegado; función en el
  repo ≠ función desplegada.
- **Links directos (preferencia del dueño):** cuando haya que pegar o desplegar
  algo, dar el link *raw* de GitHub **fijado al commit probado** (verificar que
  responde 200 y coincide con el archivo probado) y el link directo del
  dashboard: SQL `https://supabase.com/dashboard/project/bxlzipwxyxdtffnuizbz/sql/new`,
  función `https://supabase.com/dashboard/project/bxlzipwxyxdtffnuizbz/functions/<nombre>`
  (pestaña Code → Deploy).
- **Banco de pruebas en un sandbox nuevo:**
  `bash supabase/pruebas/local/herramientas/preparar.sh` (PostgreSQL 15, Deno,
  Playwright, Pillow en `/projects/sandbox/pruebas-em5`). Luego:
  - SQL: `pg.sh <archivos de supabase/pruebas/local/*.sql>` (incluye la matriz 170/170);
  - `dropi-sonda`: `correr-dropi-sonda-d1.sh` (40/40);
  - pantallas de Dropshipping: `correr-ui-dropshipping.sh` (D1 54/54, D2a 60/60);
  - GitHub Actions corre el banco en cada push a una rama que toque `supabase/**`.
- Recordatorio del sandbox: los procesos en segundo plano no sobreviven entre
  llamadas; todo lo que necesite servidor va en un solo comando.
- Secretos (`DROPI_TOKEN`, `service_role`, Wompi) solo en Edge Functions;
  nunca en frontend, repo, chat ni logs.
